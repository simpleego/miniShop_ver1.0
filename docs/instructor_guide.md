# 강사 가이드

> 10일 실습 과정을 진행하는 강사를 위한 문서입니다. 일차별 문서 끝의 **📌 강사 메모**와 함께 보세요.

---

## 1. 이 과정을 이렇게 설계한 이유

| 설계 | 이유 |
|---|---|
| MVP(1~5일) → 확장(6~10일) | 첫 주에 **돌아가는 결과**를 봐야 동기가 유지된다 |
| 기능 하나 = DB → API → 화면 | 매일 같은 틀을 반복해 **패턴**이 몸에 익는다 |
| 일부러 **허술한 코드를 먼저** 만들고 고친다 (4→5일차) | 문제를 직접 **재현**해 봐야 "왜 이렇게 해야 하는지"가 남는다 |
| 패키지·테이블을 **필요할 때** 추가 | 도구의 존재 이유를 이해한다 |
| 일차별 **스냅샷** | 뒤처진 학생이 같은 출발선으로 돌아올 수 있다 |
| 긴 코드·CSS 는 **📦 제공** | 학습 목표(개발 과정)에 시간을 집중한다 |

## 3. 일차별 핵심 메시지와 시연

| 일 | 학생이 가져가야 할 한 문장 | 꼭 보여 줄 시연 |
|---|---|---|
| 1 | "개발은 코딩이 아니라 **무엇을 만들지 정하는 것**부터다" | 완성본 5분 시연, MVP 정하기 활동 |
| 2 | "기능 하나는 **DB → API → 화면**" | JSON 화면과 카드 화면 **나란히**, DB 비번을 틀리게 해서 500 보기 |
| 3 | "**주소가 곧 화면**이고, 공유 데이터는 Context 에" | `useCart` 를 두 곳에서 호출했을 때 배지가 안 바뀌는 상황 |
| 4 | "여러 단계는 **전부 성공 or 전부 취소**" | 롤백 시험(실패했는데 재고가 안 줄었다), mysql 창 두 개 트랜잭션 |
| 5 | "**확인하고 행동하는 사이의 틈**이 버그가 된다" | 재고 **-2** 나오는 `race_test.py` |
| 6 | "비밀번호는 **해시**, 증명은 **토큰**" | 같은 비밀번호의 서로 다른 해시, 토큰 위조 → 401 |
| 7 | "**내 데이터만** 보이게 하는 것은 서버의 책임" | 남의 주문 조회 → 404 (`AND user_id` 를 지우면 보이는 것도) |
| 8 | "**사용자가 입력한 글자는 SQL 에 이어 붙이지 않는다**" | `ORDER BY` 인젝션(연습 DB), `%` 검색 |
| 9 | "**권한은 서버에서**, 화면은 편의" | 일반 회원 토큰으로 `/docs` 에서 관리자 API → 403 |
| 10 | "파일은 **믿지 않고**, 실패하면 **직접 지운다**" | 이름만 jpg 인 텍스트 파일 → 422 |

## 4. 시간이 모자랄 때 (생략 우선순위)

일정이 밀리면 아래 순서로 **줄입니다.** (앞의 것부터)

| 우선순위 | 줄이는 방법 | 영향 |
|---|---|---|
| 1 | 10일차 **비밀번호 재설정** 생략 | 없음 (선택 과제) |
| 2 | 8일차 **페이지 번호 UI** 를 과제로, 정렬 드롭다운은 복사 | 작음 |
| 3 | 9일차 **주문 관리 화면**은 시연, API 만 `/docs` 로 시험 | 작음 |
| 4 | 10일차 **이미지 화면**은 시연, 서버 코드는 읽기만 | 중간 |
| 5 | 7일차 **결제 화면**은 복사만, 핵심 4곳만 설명 | 중간 |
| 6 | 6일차 **Gmail 연동**은 개발 모드로 대체 | 작음 |

> **절대 줄이지 않는 것** : 2일차 DB→API→화면 흐름, 4일차 롤백 시험, 5일차 동시성 실험, 6일차 해시·토큰 개념, 8일차 SQL 인젝션 방어, 9일차 권한(403). 이 6가지가 과정의 **핵심 경험**입니다.

## 5. 수강생 수준 차이 다루기

| 상황 | 대응 |
|---|---|
| 속도가 빠른 학생 | 일차별 **도전 과제**, 다른 학생 돕기(짝 프로그래밍) |
| 뒤처진 학생 | `docs/steps/dayNN` 을 **겹쳐 복사**해 같은 출발선에 세운 뒤, 원리는 쉬는 시간에 설명 |
| 환경 문제로 막힘 | 한 명 때문에 전체를 멈추지 않는다. 조교/옆 학생이 돕고 **먼저 동작시킨 뒤** 원리 설명 |
| 문법(`map`, `...`, `async`)이 낯섦 | 종이에 **손으로 한 줄씩 따라가기**. 개념보다 **값이 어떻게 바뀌는지**를 보여 준다 |
| 오류 메시지에 겁먹음 | **오류 읽는 법**을 가르친다 : 맨 아래 줄 → 어느 파일 몇 번째 줄 → 영어 문구 검색 |

## 6. 자주 막히는 지점 (FAQ)

| 증상 | 원인 | 빠른 해결 |
|---|---|---|
| 서버가 안 켜짐, `No module named 'app'` | 실행 위치 | `backend` 폴더에서 `python -m uvicorn app.main:app` |
| PowerShell 가상환경 활성화 오류 | 실행 정책 | `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` 또는 `python -m` 방식 |
| 화면에서 API 가 404 | 프록시 추가 후 Vite 재시작 안 함 | **Vite 재시작** (가장 흔함) |
| 한글이 `???` | mysql 접속 문자셋 | `--default-character-set=utf8mb4` |
| 새로고침하면 화면에 JSON | 화면 주소가 API 주소와 같음 | 화면 `/product`, API `/products` |
| 5일차 결과가 문서와 다름 | MariaDB 버전 차이 | 5일차 문서의 "버전에 따라 다르다" 설명 참고 |
| 메일이 안 옴 | SMTP 설정/네트워크 | [Gmail 가이드 6장](guide_gmail_smtp.md), 개발 모드 |
| 주소 검색 창이 안 뜸 | 외부 스크립트 차단 | 네트워크 확인, 직접 입력으로 임시 대체 |
| `.env` 를 깃에 올릴 뻔함 | `.gitignore` 누락 | `git status` 로 확인 습관 |

## 7. 보안·정보 사고 방지

- **앱 비밀번호, DB 비밀번호, `JWT_SECRET` 은 화면에 띄우지 않습니다.** (프로젝터에 `.env` 를 열어 두지 않기)
- 수강생이 **채팅·메신저에 비밀번호를 붙여넣지 않도록** 안내합니다. 노출되었다면 **즉시 폐기**(앱 비밀번호 삭제, DB 비밀번호 변경)합니다.
- 실습용 DB(`test_vmshop`)는 **운영 DB 와 분리**되어 있음을 강조합니다.
- 실험(5일차 `CHECK` 제약 제거, 8일차 인젝션 시연) 후에는 **반드시 원상 복구**하게 합니다.

## 8. 평가 루브릭 (선택)

점수보다 **성장**을 보기 위한 4단계 기준입니다.

| 영역 | 도전 중 | 이해함 | 설명 가능 |
|---|---|---|---|
| 개발 과정 | 순서를 따라 함 | DB→API→화면을 안다 | **왜 그 순서인지** 설명 |
| 서버 | 코드를 따라 침 | API 하나를 혼자 추가 | 오류 코드(401/403/404/409/422)를 구분해 설계 |
| DB | SELECT 를 씀 | JOIN·GROUP BY 를 씀 | 설계 이유(표를 나눈 이유)를 설명 |
| 화면 | 복사해서 동작시킴 | state·props 를 구분 | 계산값과 state 를 구분해 설계 |
| 보안 | 규칙을 안다 | 인젝션·해시·권한을 구별 | **공격 예시와 방어**를 말로 설명 |
| 협업·태도 | | 오류 메시지를 읽고 시도 | 팀원에게 설명 |
